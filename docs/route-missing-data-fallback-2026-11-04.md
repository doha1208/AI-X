# 경로 자료 부족 시 단계별 평가 보완

## 재현

사용자 제공 경로: 경기 화성시 병점구 반정동 92-2 → 경기도 수원시 권선구 권광로109번길 12, 주간.
공식 주소검색으로 각 주소의 단일 일치 결과를 확인하고 실제 경로 API를 호출했다. 전 구간 공통 지표는 비상벨 하나이며, CCTV는 화성 구간 때문에 outside_source_coverage, 상점은 opening_hours_unverified이다. 주변 관측은 비상벨17·CCTV19·상점51 좌표인데 최소 두 지표 조건으로 score=null이었다.

## 구현 범위

1. 기존 종합 score는 두 개 이상 전 구간 공통 지표가 있을 때 유지한다. 하나면 reference_score와 reference_factor를 반환하고 ‘비상벨 참고 N점’처럼 표시한다. 단일 지표를 종합 점수로 부르지 않는다.
2. 공식 원본·취득·범위·목적 근거가 있는 부분 자료는 확인된 시설의 존재 근거로 활용한다. 좌표 누락 지역에서 미발견을 부재로 바꾸지는 않는다. 출처 없는 기존 좌표나 시간 미확인 상점을 검증 지표로 승격하지 않는다.
3. 경로를 기존 20m 셀로 나눠 지표별 평가 가능 거리 비율을 계산한다. 완전 수집 범위 내 셀은 존재/미관측을 구분할 수 있고, 부분 수집 자료는 실제 인접한 시설의 존재만 확인한다.
4. 전 구간 공통 지표도 없지만 일부 자료가 있으면 단일 수치를 만들지 않고 접근성의 하한·상한을 반환한다. 활성 지표를 동일 비중으로 두고 확인된 존재를 하한, 확인된 존재와 미확인 영역을 상한에 반영한다. 이 범위는 통계적 신뢰구간이나 범죄 확률이 아니다. 아무 근거도 없으면 점수는 계속 미상이다.
5. 비교 일반 경로에서 사용할 수 있는 지표를 보존한다. 그 지표를 공유하지 못하는 대안 하나 때문에 정상 후보 전체의 지표를 제거하지 않는다. 단일 지표 참고 비교도 같은 지표·같은 그룹 안에서만 하고, 5점 한도를 유지한다. 부분 자료의 범위만 있는 후보는 수치로 순위를 만들지 않고 일반 경로 안내를 유지한다.
6. 카드 크기는 유지하며 요약에 평가 종류를 표시하고 부분 적용 범위와 제외 이유는 접힌 상세로 둔다. 참고 점수를 종합 추천으로 표시하지 않는다.

## 파일과 검증

- backend/app/services/route_environment_sources.py: 전체/존재 근거의 자격과 범위 캐시.
- backend/app/services/route_environment_evidence.py: 셀별 확인 범위와 불확실성 범위 계산.
- backend/app/services/route_environment.py, route_environment_rank.py: 참고 평가와 비교 후보 구성.
- backend/app/schemas/safety.py, frontend/src/lib/api.ts: 기존 score 의미를 유지하는 추가 필드.
- frontend/src/lib/routeGuidance.ts, RouteEnvironmentSummary.tsx, route/page.tsx, navigate/ChoicePanel.tsx: 평가 종류별 요약·상세.
- 단일 지표, 알려진0, 부분 좌표, 시간 미확인, 자료 없는 경우, 후보 하나의 범위 부족, 비교 기준 혼합 방지를 회귀 검증한다.
- 사용자 경로와 화성·수원·부천·광명·김포 등 다른 지역의 실제 경로를 낮/밤으로 검증한다. 거주지 점수·반경·우회 제한·5점 허용 차이는 바꾸지 않는다.
