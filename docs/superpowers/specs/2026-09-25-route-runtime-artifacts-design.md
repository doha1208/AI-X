# 경로 런타임 산출물 설계

## 목표

임의 좌표 기반 길찾기와 실시간 재경로 기능은 유지하되, 정적인 경로 준비 작업을 HTTP 요청에서 분리한다. 데이터가 갱신되면 버전이 있는 신뢰 가능한 경로 산출물을 만들고, API 워커는 최신의 유효한 산출물을 읽어 좌표 스냅과 최단 경로 탐색만 수행한다.

## 범위와 전제

- 초기 서비스 범위는 서울·경기이며, 이후 전국 확장을 위해 산출물 형식은 설정된 지역별 산출물을 지원한다.
- 경로 산출물은 FastAPI 내부의 고정 주기 타이머가 아니라 공공데이터 적재가 성공적으로 끝난 뒤 다시 생성한다.
- 하나의 데이터 버전에 대해 낮과 밤의 점수 그래프를 각각 정적으로 생성한다.
- 기존 경로 계약인 `safety_weighted → tmap → straight_line` 폴백 순서는 유지한다.
- 사용자는 임의의 출발지와 도착지 좌표를 입력할 수 있으므로, 가능한 모든 경로를 미리 계산할 수는 없다.

## 산출물 수명주기

1. 기존 데이터 적재 배치가 끝나고 데이터 버전을 검증한다.
2. 새 배치 명령이 신뢰 가능한 로컬 OSM 보행 그래프, 안전구역, 시설 데이터를 읽는다.
3. 노드 공간 색인과 낮·밤용 불변 안전 가중 그래프를 만들고, 버전이 붙은 산출물과 매니페스트를 설정된 산출물 디렉터리에 쓴다.
4. 모든 산출물 파일을 쓰고 검증한 뒤에만 작은 `current` 매니페스트 포인터를 원자적으로 교체한다.
5. 각 API 워커는 기동 시 매니페스트의 산출물을 읽는다. 새로고침 신호 또는 제한된 주기의 매니페스트 확인으로 완전한 새 산출물만 로드하며, 부분적으로 만들어진 산출물은 노출하지 않는다.

산출물은 애플리케이션이 소유하는 데이터로만 구성한다. 사용자 입력으로 만들거나 교체하지 않는다. NetworkX 객체에 pickle을 계속 사용한다면, 신뢰 가능한 애플리케이션 산출물 디렉터리에 한정해서 읽는다.

## 런타임 경로 탐색

`safe_route`는 로드된 산출물에 대한 런타임 진입점이 된다.

1. 미리 만든 공간 색인으로 출발지와 도착지에 가장 가까운 노드를 찾는다.
2. 요청 시점의 낮·밤 구분에 맞는 불변 그래프를 선택한다.
3. 현재의 최단 경로 알고리즘을 실행한다. 기존 대안 경로 임계값보다 긴 요청은 안전 경로 하나만 반환한다.
4. 산출물 버전, 낮·밤 구분, 출발 노드, 도착 노드, 대안 경로 개수를 키로 한 제한된 결과 캐시를 저장한다.

이 방식은 도로 노드 기준의 정확한 경로를 유지하면서 반복 검색과 가까운 위치에서의 실시간 재경로에 결과를 재사용하게 한다. 데이터 산출물 버전이 바뀌면 캐시 항목은 자동으로 무효화된다.

## 외부 경로 서비스 동작

Tmap은 안전 가중 엔진이 경로를 반환하지 못할 때 계속 사용한다. 다만 비교용 최단경로는 더 이상 모든 요청에서 무조건 호출하지 않는다. 클라이언트가 명시적으로 비교를 요청할 때만 호출·반환하고, 별도의 제한된 캐시를 둔다. 프런트엔드는 사용자가 직접 경로를 검색할 때 비교를 요청해 기존 비교 화면을 유지한다. 자동 실시간 재경로에서는 안전 경로만 요청한다.

## 책임과 인터페이스

- 배치 계층은 산출물 생성과 게시를 담당한다.
- `safe_route`는 산출물 로드, 경로 조회, 캐시 무효화, 산출물 부재 시의 안전한 처리를 담당한다.
- `safety.py`는 검증과 응답 조합, Tmap 비교 요청 여부를 담당한다.
- 프런트 API 클라이언트는 명시적인 비교 옵션을 추가한다. 실시간 재경로는 이 옵션을 끈다.

API 응답은 하위 호환성을 유지한다. `shortest_route_points`는 계속 nullable이며, 새 선택 요청 필드는 현재의 사용자 직접 검색 비교 동작을 기본값으로 둔다.

## 오류 처리와 준비 상태

- 산출물이 없거나 손상되었거나 오래됐더라도 HTTP 요청 중에 비용이 큰 산출물 생성을 실행하지 않는다.
- 산출물이 해당 좌표의 경로를 찾지 못하면 기존 Tmap·직선 폴백 순서를 적용한다.
- 산출물 로드 실패는 좌표·토큰·사용자 식별자를 남기지 않고 기록한다.
- 이후 readiness 점검은 내부 경로를 공개하지 않고 산출물 버전과 사용 가능 상태를 제공할 수 있다.

## 검증

- 배치 테스트는 결정론적인 매니페스트 게시을 확인하고, 불완전하거나 손상된 산출물을 거부한다.
- 런타임 테스트는 산출물 로드, 최근접 노드 경로 탐색, 낮·밤 그래프 선택, 버전 기반 결과 캐시 무효화, 경로 없음 폴백을 다룬다.
- API 테스트는 선택적 비교 동작과 기존 폴백 응답 계약을 확인한다.
- 프런트 테스트는 직접 검색 시의 비교와 비교 없는 실시간 재경로를 확인한다.

## 단계별 구현 단위

1. 산출물 모델, 매니페스트, 신뢰 가능한 원자적 기록, 테스트
2. 기존 로컬 OSM 그래프와 점수 계산 코드를 사용하는 배치 산출물 생성기
3. 런타임 산출물 로더와 `safe_route` 경로 조회 전환, 기존 폴백 계약 유지
4. 버전 기반 결과 캐시와 산출물 재로드·무효화 동작
5. 선택적 Tmap 비교 API 필드와 프런트 실시간 재경로 연동
6. 배포·데이터 갱신 문서화, readiness, 회귀 테스트
