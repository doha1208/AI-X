# Phase 1 — 구성 가능한 안전점수·산출물 운영 설계

## 목표

안전점수의 가중치와 누락 데이터 처리 기준을 코드 배포 없이 관리자가 조정할 수 있게 한다. 새 점수 정책이나 새 공공데이터는 완전히 검증된 뒤에만 거주지 추천과 안전 경로에 함께 반영한다. 생성 실패나 외부 데이터 실패가 현재 사용자 응답을 망가뜨리면 안 된다.

이 설계의 초기 운영 대상은 지속적인 대규모 서비스가 아닌 별도 서버 또는 컨테이너에 배포하는 데모다. 따라서 복잡한 범용 규칙 엔진이나 다단계 권한 관리 대신, 한정된 관리자와 명시적인 버전 관리에 집중한다.

## 합의된 운영 정책

- 외부·공공 데이터는 30분마다 갱신 여부를 확인한다. 새 데이터가 없으면 재계산하지 않는다.
- 점수 프로필 변경은 즉시 새 산출물 생성을 요청한다. 30분 주기는 데이터 확인 주기이지, 그래프 강제 재생성 주기가 아니다.
- API 워커는 새 `current` 산출물 포인터를 짧은 주기(기존 60초)로 확인한다. 새 산출물이 검증됐을 때만 메모리의 런타임 산출물을 교체한다.
- 관리자는 서버 설정의 허용 이메일 목록으로 정한다. 일반 로그인 사용자는 점수 설정을 조회·변경할 수 없다.
- 저장소 작업자는 Git 커밋·스테이징·푸시를 수행하지 않는다. 각 작은 구현 단위의 검증 결과와 권장 커밋 메시지만 제공한다.

## 범위

### 관리자가 바꿀 수 있는 값

점수 프로필은 아래의 선언형 정책만 포함한다.

- 낮과 밤 각각의 CCTV, 보안등, 범죄율, 경찰서 거리, 상점 수, 비상벨 거리 가중치
- 각 요인의 데이터가 `None` 또는 미수집일 때 쓸 중립 점수
- 프로필 이름, 설명, 생성 시각, 버전, 상태

각 시간대 가중치의 합은 정확히 1.0이어야 하며, 모든 가중치는 0 이상이어야 한다. 지원하는 요인의 집합과 정규화 방법(min-max), 낮·밤 판정, 거리 계산 방식은 코드에 유지한다. 새 요인을 추가하거나 임의 수식 자체를 바꾸는 것은 검증 가능한 코드 변경으로 취급한다.

### 이 단계에서 제외하는 것

- 여러 조직·여러 역할을 관리하는 권한 관리 화면
- 사용자별로 다른 안전점수 정책
- 외부 데이터 공급자의 실시간 보장을 가정하는 처리
- HTTP 요청 중 OSM 다운로드, 전 구간 재점수화 또는 산출물 생성

## 현재 구조에서 바로잡을 점

현재 `safety_score.py`는 낮·밤 가중치를 코드 상수로 보유하고, 일부 경로 계산용 레코드에서 `crime_rate`, `police_dist_m`, `bell_dist_m`의 빈 값을 `0`으로 치환한다. 이는 알 수 없는 값이 안전하거나 불리한 값처럼 취급될 수 있다.

모든 점수 계산 경로는 값이 없음을 `None`으로 보존하고, 활성 점수 프로필의 중립 점수를 적용해야 한다. 보안등의 `lights_known=False` 처리와 동일한 원칙을 범죄율·경찰서 거리·비상벨 거리에도 적용한다.

## 구성 요소와 책임

| 구성 요소 | 책임 |
| --- | --- |
| 점수 프로필 저장소 | 초안·활성·이전 프로필의 불변 버전과 감사 정보를 저장한다. |
| 점수 계산 서비스 | 명시적으로 전달된 프로필과 원시 안전 데이터를 사용해 낮·밤 점수를 계산한다. |
| 산출물 빌더 | 데이터 스냅샷과 후보 프로필로 점수 맵 및 낮·밤 경로 그래프를 생성·검증한다. |
| 산출물 런타임 | 최신의 검증된 산출물만 로드하고, 이전 유효 산출물을 안전한 폴백으로 유지한다. |
| 관리자 API | 관리자 인증, 프로필 검증·초안 저장·적용 요청·상태·되돌리기를 제공한다. |
| 관리자 화면 | 현재 활성 설정과 생성 상태를 보여주고 가중치 편집·적용·되돌리기를 제공한다. |
| 데이터 갱신 작업 | 30분마다 외부 데이터의 변경 여부를 확인하고, 변경이 확인된 경우에만 산출물 생성을 요청한다. |

## 일관된 점수 버전

거주지 추천과 경로 탐색은 같은 데이터·점수 프로필 조합을 사용해야 한다. 이를 위해 산출물 버전에 다음 식별자를 넣는다.

```text
산출물 버전 = 데이터 스냅샷 버전 + 점수 프로필 버전 + 생성 시각
```

산출물에는 낮·밤의 행정동별 점수 맵과 경로 그래프를 함께 넣는다. 런타임은 이 점수 맵을 경로 결과의 통과 지역 점수와 거주지 추천의 정렬 기준으로 사용한다. 따라서 새 프로필이 편집·저장된 것만으로 서비스 결과가 섞이지 않으며, 새 산출물이 `current`로 게시된 순간에만 두 기능이 같은 버전으로 전환된다.

산출물 부재·손상·재로드 실패 시에는 마지막으로 메모리에 정상 로드된 산출물을 유지한다. 서버가 처음 시작했고 유효 산출물이 전혀 없으면 경로는 기존 `tmap → straight_line` 폴백을 사용하고, 상태 API는 산출물 부재를 명확히 표시한다. API가 요청 도중 새 산출물을 만들지는 않는다.

## 관리자 설정 흐름

1. 허용 이메일의 관리자가 로그인해 현재 활성 프로필과 이전 버전을 조회한다.
2. 관리자는 낮·밤 가중치와 중립 점수를 편집해 새 초안을 저장한다. 기존 활성 버전은 수정하지 않는다.
3. 서버는 범위·합계·지원 요인 검증을 통과한 초안에 대해 산출물 빌더 작업을 요청한다.
4. 빌더는 고정된 데이터 스냅샷과 초안 프로필을 읽어 점수 맵과 경로 그래프를 만들고, 파일 무결성과 기본 경로 탐색을 검증한다.
5. 빌드 성공 시에만 새 버전 산출물을 원자적으로 게시하고 프로필을 활성 상태로 전환한다. 실패하면 초안은 실패 상태와 원인을 보유하고, 이전 활성 프로필·산출물은 그대로 남는다.
6. 관리자는 이전 활성 프로필을 다시 적용할 수 있다. 이는 기존 산출물을 단순히 덮어쓰지 않고 해당 프로필의 새 검증 산출물을 만드는 일반 적용 흐름을 따른다.

관리자 화면은 권한이 없는 사용자에게 노출하지 않는 것으로 충분하지 않다. 모든 관리자 API도 서버 쪽에서 허용 이메일과 유효한 access token을 확인해야 한다.

## API와 사용자 경험

관리자 API는 다음의 목적별 인터페이스로 제한한다. 최종 URL과 요청·응답 스키마는 구현 계획에서 기존 FastAPI 관례에 맞춰 확정한다.

- 현재 활성 프로필과 최근 이력을 읽기
- 새 초안 저장 및 유효성 오류 반환
- 초안 적용 요청과 빌드 상태 읽기
- 이전 프로필을 새 적용 대상으로 선택

관리자 화면은 다음을 보여준다.

- 낮·밤별 여섯 가중치와 합계(합계가 1.0이 아니면 적용 불가)
- 누락 데이터 중립 점수
- 현재 활성 버전, 사용 데이터 버전, 마지막 적용 시각
- 생성 중·성공·실패 상태 및 사용자에게 안전한 실패 안내
- 이전 버전 목록과 되돌리기 버튼

일반 사용자 화면은 기존 조회·경로 경험을 유지한다. 새 산출물로 전환된 뒤의 점수만 보이며, 초안·내부 파일 경로·외부 API 키·예외 상세는 노출하지 않는다.

## 컨테이너 배포

초기 배포는 Docker Compose 기준으로 분리한다.

```text
관리자 화면·일반 화면 ──> API 컨테이너 ──> 데이터베이스
                                  │
                                  ├──> 공유 영속 산출물 볼륨
                                  │
수집/빌더 컨테이너 ────────────────┘
```

- API 컨테이너는 FastAPI 요청과 검증된 산출물 조회만 담당한다.
- 수집/빌더 컨테이너는 30분 확인 작업, 데이터 적재, 점수·경로 산출물 생성을 담당한다.
- 두 컨테이너는 신뢰 가능한 영속 볼륨을 통해 버전 산출물과 작은 `current` 매니페스트를 공유한다.
- 산출물을 쓰는 쪽은 임시 위치에서 완성·검증한 뒤 `current` 포인터만 원자적으로 교체한다.
- 향후 다중 서버가 필요해지면 영속 볼륨을 관리형 오브젝트 스토리지로 교체할 수 있으나, 초기 데모에서 이를 미리 도입하지 않는다.

## 오류 처리

| 상황 | 동작 |
| --- | --- |
| 외부 데이터 확인 실패 | 이전 데이터·산출물을 유지하고 다음 주기에 재시도한다. |
| 데이터는 새롭지만 산출물 생성 실패 | 새 버전을 게시하지 않고 실패 상태를 관리자에게 표시한다. |
| 프로필 가중치 합계·범위 오류 | 초안 저장 또는 적용 전에 명확한 검증 오류를 반환한다. |
| 산출물 무결성·스키마 오류 | 새 산출물을 채택하지 않고 현재 메모리 산출물을 계속 사용한다. |
| 초기 산출물 부재 | 경로 API는 Tmap·직선 폴백을 사용하고 상태를 명확히 표시한다. |
| 권한 없는 설정 요청 | 401 또는 403으로 거절하며 설정 내용을 변경하지 않는다. |

## 점진적 구현 단위

각 단위는 독립적으로 검증한 뒤 사용자에게 넘기며, 저장소 작업자는 커밋하지 않는다.

1. **누락값 중립 처리** — 원시 모델·적재·점수 계산에서 `None`을 보존하고 범죄율·경찰서·비상벨에 중립 처리를 적용한다.
2. **점수 프로필 계산 구조** — 기존 기본값과 동일한 기본 프로필을 만들고, 점수 계산 함수가 하드코딩 상수 대신 명시적 프로필을 받게 한다.
3. **관리자 권한·프로필 저장** — 허용 이메일 확인, 프로필 초안·버전·검증·조회 API를 추가한다.
4. **안전한 적용 파이프라인** — 후보 프로필과 데이터 스냅샷으로 산출물을 만들고, 성공한 버전만 원자적으로 활성화한다.
5. **거주지·경로 일관성** — 런타임 산출물의 점수 맵을 두 기능이 함께 사용하도록 전환하고, 버전 혼합을 막는다.
6. **관리자 화면** — 편집, 합계 검증, 적용 상태, 이력, 되돌리기를 제공한다.
7. **컨테이너 운영 연결** — Compose 서비스, 영속 볼륨, 30분 데이터 확인과 관측 가능한 빌드 상태를 추가한다.

## 검증 전략

- 점수 테스트: 누락값은 0으로 취급되지 않고, 기본 프로필은 기존의 알려진 데이터 결과를 유지한다.
- 프로필 테스트: 지원하지 않는 요인, 음수 가중치, 시간대별 합계 오류, 잘못된 중립 점수를 거절한다.
- 권한 테스트: 일반 사용자와 토큰 없는 요청은 관리자 API를 호출할 수 없다.
- 적용 테스트: 실패한 빌드는 활성 프로필·`current` 포인터·기존 런타임 결과를 바꾸지 않는다.
- 일관성 테스트: 같은 산출물 버전에서 거주지 순위, 통과 구역 점수, 경로 비용이 같은 프로필을 사용한다.
- 런타임 테스트: 새 유효 매니페스트는 로드하고, 손상된 매니페스트는 거절하며, 산출물 부재는 기존 폴백 응답을 유지한다.
- 프런트 검증: 관리자 화면은 권한 없는 진입을 막고, 클라이언트 검증 오류·서버 실패·생성 상태·되돌리기를 정확히 표시한다.
- 배포 검증: API와 수집/빌더가 같은 영속 산출물 디렉터리를 사용하며, 데이터 변경이 없을 때 불필요한 재생성을 하지 않는다.

## 완료 기준

- 관리자가 배포 없이 지원 요인의 낮·밤 가중치와 중립 점수를 변경할 수 있다.
- 변경된 설정 또는 데이터는 검증된 새 산출물 하나로 거주지 추천과 경로 계산에 함께 적용된다.
- 누락 데이터는 안전 점수를 부당하게 올리거나 내리지 않는다.
- 빌드·외부 데이터·산출물 오류가 있어도 마지막 정상 결과 또는 기존 경로 폴백이 유지된다.
- 일반 사용자는 관리자 기능과 내부 운영 정보를 볼 수 없고 설정을 바꿀 수 없다.
